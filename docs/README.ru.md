Лёгкий и выразительный робот-аватар Web Component для AI-агентов и других интерактивных приложений.

Подходит для интерфейсов AI-ассистентов и агентов, включая продукты и сценарии, похожие на ChatGPT, Claude, Codex, Cursor, Grok Bot, Gemini CLI и OpenCode.

Также может использоваться для desktop pets, виртуальных питомцев, настольных компаньонов, цифровых маскотов, аватаров чат-ботов и других интерактивных персонажей.

Agent Robot Avatar также может служить визуальным слоем обратной связи для интерфейсов агентов в стиле AG-UI.

Agent Robot Avatar построен на SVG и vanilla JavaScript. Он не зависит от сторонних анимационных фреймворков, работает как нативный Custom Element и предоставляет компактный API для выражений, интерактивных состояний, поведения указателя, ожидания и настройки формы головы.

**Текущая публичная версия: v0.3.2**

## Быстрый старт

При использовании исходников репозитория напрямую держите `agent-robot-avatar.js` рядом с каталогом `src/`, затем подключите публичную точку входа:

```html
<script type="module" src="./agent-robot-avatar.js"></script>
```

Добавьте Custom Element:

```html
<agent-robot-avatar id="avatar"></agent-robot-avatar>
```

Аватар автоматически переходит в стандартное idle-поведение. Дополнительная инициализация не требуется.

Минимальный запускаемый пример находится в [`examples/basic.html`](../examples/basic.html). Пример интеграции с акцентом на доступность находится в [`examples/accessibility.html`](../examples/accessibility.html).

В проектах с bundler компонент можно установить из npm:

```bash
npm install agent-robot-avatar
```

```js
import 'agent-robot-avatar';
```

Пакет включает TypeScript-декларации для действий, событий и публичных методов. Никакой отдельной настройки TypeScript сверх обычной установки пакета не требуется.

## Базовый API

Запустить выражение или состояние через `play()`:

```js
const avatar = document.querySelector('#avatar');

avatar.play('success');
avatar.play('failure');
avatar.play('warning');
avatar.play('inspect');
avatar.play('blocked');
avatar.play('error');
```

Вернуться в стандартное idle-состояние:

```js
avatar.reset();
```

`reset()` отменяет текущее программное действие, ожидающие операции, анимации головы, drag/rebound-состояние и отложенные реакции перетаскивания, после чего возвращает аватар в idle. Promise отменённых анимаций по-прежнему нормально разрешаются, а не отклоняются. Удаление элемента выполняет ту же внутреннюю очистку без служебных уведомлений `face-state` и `action-state`, а также снимает медиазапросы и observers конкретного экземпляра без побочного перезапуска отрисовки. После повторного подключения компонент начинает с idle, сохраняет настройки внешнего вида и поведения и один раз устанавливает необходимые runtime-ресурсы.

Новое корректное действие заменяет предыдущее активное действие. Предыдущее семантическое действие получает `cancel` и не может позднее возобновиться и перезаписать новое состояние. Неизвестное действие выбрасывает ошибку до разрушительной очистки. No-op-вызов, например `wake` при уже бодрствующем аватаре, не изменяет активное действие.

## Действия и состояния

| Состояние | Имя API | Назначение |
| --- | --- | --- |
| Idle | `idle` | Стандартное состояние ожидания |
| Bored | `bored` | Длительный простой или отсутствие активной задачи |
| Waiting | `waiting` | Запрос отправлен, результат ещё ожидается |
| Input | `input` | Пользователь вводит текст |
| Send | `send` | Контент отправлен / подтверждение кивком |
| Success | `success` | Задача успешно завершена |
| Failure | `failure` | Задача завершилась неуспешно |
| Warning | `warning` | Рискованное или разрушительное действие требует подтверждения |
| Inspect | `inspect` | Проверка, анализ или верификация результата |
| Blocked | `blocked` | Запрос заблокирован, запрещён или не может быть выполнен |
| System error | `error` | Ошибка соединения, сервиса или системы |
| Surprise | `surprise` | Неожиданное событие или результат |
| Sleep | `sleep` | Перевести компонент в состояние сна |
| Wake | `wake` | Разбудить компонент |

Названия состояний намеренно отделяют результат задачи от состояния системы. Например, `failure` означает, что запрошенная задача завершилась неуспешно, а `error` предназначен для ошибок соединения, сервиса или системы. `waiting` означает активное ожидание запроса, а `bored` — отсутствие активности. `sleep` описывает только состояние компонента-аватара и не означает, что реальный Agent офлайн.

Также доступны семантические алиасы:

```js
avatar.play('failed');           // то же, что failure
avatar.play('fail');             // то же, что failure
avatar.play('verify');           // то же, что inspect
avatar.play('review');           // то же, что inspect
avatar.play('angry');            // то же визуальное выражение, что blocked
avatar.play('policy-blocked');   // то же, что blocked
avatar.play('system-error');     // то же, что error
avatar.play('connection-error'); // то же, что error
```

## Непрерывное ожидание

Для реальных Agent-процессов используйте отдельный жизненный цикл waiting, пока запрос находится в работе:

```js
avatar.startWaiting();

// Остановить, когда запрос завершён и не заменяется другим действием.
avatar.stopWaiting();
```

`startWaiting()` остаётся активным до `stopWaiting()`, `reset()` или замены другим программным действием. Замена сообщает `cancel`; `stopWaiting()` сообщает нормальный `end`, когда waiting активно. Для обратной совместимости вызов `stopWaiting()` во время другого активного программного действия всё ещё возвращает аватар в idle; это действие теперь получает ровно один `cancel`. Вызов без активного действия не создаёт искусственное событие жизненного цикла. Drag-деформация остаётся доступной во время waiting, но декоративные drag-выражения подавляются и отбрасываются, а не проигрываются после завершения ожидания.

Типичный жизненный цикл запроса:

```js
avatar.startWaiting();
try {
  const result = await runAgentRequest();
  await avatar.play(result.ok ? 'success' : 'failure');
} catch (error) {
  await avatar.play('error');
}
```

Визуальное действие `error` со временем возвращается в idle. Завершение этой визуальной анимации не означает, что исходная ошибка запроса, соединения или бизнес-логики устранена; хост-приложение остаётся источником истины.

## Семантическое событие действия

`face-state` сохраняется для обратной совместимости и описывает визуальные состояния лица. Оно может содержать термины вроде `happy` или `sad`, поэтому его не следует использовать как надёжное событие результата бизнес-операции.

Для семантической интеграции слушайте `action-state`:

```js
avatar.addEventListener('action-state', (event) => {
  const { action, phase, source } = event.detail;
  console.log(action, phase, source);
});
```

Контракт `action-state`:

- `action`: нормализованное имя действия. Алиасы `failed`/`fail` становятся `failure`; `verify`/`review` становятся `inspect`.
- `phase`: `start`, после которого для каждого реально запущенного действия ровно один раз следует `end` или `cancel`.
- `source`: `api`, `interaction` или `automatic`.
- Непрерывные действия вроде `startWaiting()` и активного input не отправляют `end` только потому, что закончился один цикл анимации.
- Замена или `reset()` отправляет `cancel`; `stopWaiting()` отправляет `end` для активного waiting либо `cancel` для другого активного действия, которое он сбрасывает в idle.
- No-op-вызовы не создают событий жизненного цикла.
- Декоративная drag-реакция использует `action: "reaction"` и `source: "interaction"`, поэтому её нельзя перепутать с API-результатом задачи.
- Событие всплывает и имеет `composed`, поэтому его можно слушать выше границы Custom Element / Shadow DOM.
- Очистка при отключении проходит тихо и не создаёт ложных статусных уведомлений для хоста.

Событие описывает действия аватара, а не реальные результаты запроса. Хост-приложение само определяет фактическое состояние Agent.

## Интеграция доступности

Для доступного текстового статуса сопоставляйте программные действия с локализованным текстом хоста, а не озвучивайте каждое визуальное изменение:

```html
<div id="agent-status" role="status" aria-live="polite"></div>
```

```js
const status = document.querySelector('#agent-status');
const messages = {
  waiting: 'Обработка…',
  failure: 'Задача завершилась неуспешно.',
  error: 'Проблема с соединением.',
};

avatar.addEventListener('action-state', ({ detail }) => {
  if (detail.source === 'interaction') return;
  if (detail.phase === 'start' && messages[detail.action]) {
    status.textContent = messages[detail.action];
  }
});
```

Используйте обычный `role="status"` для рутинных обновлений. Не озвучивайте моргание, движения взгляда и декоративные drag-реакции и не превращайте автоматически каждую ошибку в прерывающий alert. Если хост уже озвучивает тот же статус в другом месте, аватар может оставаться декоративным, чтобы избежать дублирования screen reader.

См. [`examples/accessibility.html`](../examples/accessibility.html) — запускаемый пример жизненного цикла запроса с waiting, success, failure, ошибками соединения, отменой со стороны хоста, заменой запроса и защитой от устаревших результатов. Текст live region следует состоянию запроса хоста, а не низкоуровневым изменениям лица.

## Политика пробуждения

Атрибут `wake-on` управляет автоматическим пробуждением:

```html
<agent-robot-avatar wake-on="manual"></agent-robot-avatar>
```

| Значение | Поведение |
| --- | --- |
| `activity` | По умолчанию. Активность указателя/клавиатуры на странице может разбудить аватар, сохраняя прежнее поведение. |
| `interaction` | Автоматически будит только прямое взаимодействие с этим аватаром. Другая активность на странице не будит его. |
| `manual` | Активность окружения, включая прямое взаимодействие с аватаром, не вызывает автоматического пробуждения. |

Явный API-вызов остаётся явным намерением: `avatar.play('wake')` будит аватар в любом режиме, а `avatar.noteActivity()` регистрирует активность и по умолчанию будит даже при вызове хостом из реального обработчика `keydown`, `pointerdown` или `click`. Передайте `false` в `noteActivity(false)`, чтобы зарегистрировать активность без пробуждения. Автоматические пробуждения от страницы или прямого взаимодействия обрабатываются отдельно и по-прежнему подчиняются `wake-on`; их источник `action-state` — `automatic`, тогда как явное пробуждение хостом остаётся `api`. Другие программные действия могут выводить компонент из сна, если их семантика требует нового видимого состояния. `reset()` всегда возвращает idle.

Разные экземпляры аватара могут использовать разные значения `wake-on`.

## Reduced motion

Атрибут `motion` управляет интенсивностью анимации:

```html
<agent-robot-avatar motion="auto"></agent-robot-avatar>
```

| Значение | Поведение |
| --- | --- |
| `auto` | По умолчанию. Следует `prefers-reduced-motion` и реагирует на изменение системной настройки во время работы. |
| `reduce` | Сохраняет узнаваемые статические состояния, подавляя непрерывное или упругое декоративное движение. |
| `full` | Использует обычный стиль анимации независимо от системной настройки reduced motion. |

В режиме reduce подавляются непрерывные орбиты waiting, idle-движения взгляда/моргания, инерция следования головы, упругий rebound, пружинное движение антенны и статусное мигание там, где это уместно. Жизненные циклы waiting/input остаются активными, пока хост не завершит или не заменит их, даже если визуальное состояние статично. Автоматический сон использует отдельный отменяемый таймер, а не draw loop, поэтому продолжает работать, когда reduced motion приостановил непрерывную отрисовку; активность и изменение `auto-sleep` во время работы перезапускают таймер, а активные waiting/input не перезаписываются. Статические изменения состояния применяются до остановки reduced-отрисовки, включая финальную позу сна с закрытыми глазами. Переключение режимов не возрождает отменённую работу и не изменяет семантику `action-state`.

## Следование за указателем

Следование за указателем включено по умолчанию и может управляться программно:

```js
avatar.setPointerFollow(false);
avatar.setPointerFollow(true);
```

Частые обновления позиции указателя объединяются до последнего значения на каждый animation frame. В обычном режиме pointer following остаётся активным, пока аватар не перетаскивается и его выражение не занято другим действием.

## Мигание антенны

Мигание статуса антенны по умолчанию выключено и может включаться отдельно для каждого аватара:

```js
avatar.setAntennaFlash(true);
avatar.setAntennaFlash(false);
```

## Настройка Inspect

Временные параметры и геометрию inspect/review можно настроить до загрузки компонента:

```html
<script>
  window.AgentRobotAvatarInspectConfig = {
    aperture: 24,
    scanOffset: 12,
  };
</script>
<script type="module" src="./agent-robot-avatar.js"></script>
```

Существующий объект конфигурации сохраняется. Значения преобразуются через `Number(...)`, должны быть конечными и ограничиваются допустимыми диапазонами; отсутствующие или некорректные значения получают значения по умолчанию. `aperture` ограничивается диапазоном `6–40`, `scanOffset` — `0–24`, а временные параметры — соответствующими диапазонами `0/40–2400 ms`. Тот же объект `window.AgentRobotAvatarInspectConfig` можно изменять после загрузки; при запуске inspect значения нормализуются повторно. Некорректный ввод не может попасть в расчёты анимации как `NaN`.

Конфигурация по умолчанию сохраняет визуальный тайминг v0.2.1.

## Округлость головы

Форму головы можно менять от более квадратной к более округлой без изменения clipping глаз или системы drag-деформации:

```js
avatar.setHeadRoundness(0);   // более квадратная
avatar.setHeadRoundness(50);  // по умолчанию
avatar.setHeadRoundness(100); // более округлая

console.log(avatar.getHeadRoundness());
```

Значения ограничиваются диапазоном `0–100`. Интерактивный Demo по умолчанию использует три пресета и может разблокировать непрерывную регулировку.

При изменении значения компонент отправляет `head-roundness-change`:

```js
avatar.addEventListener('head-roundness-change', (event) => {
  console.log(event.detail.value);
});
```

## Событие визуального состояния

Компонент продолжает отправлять `face-state` при каждом изменении визуального состояния:

```js
avatar.addEventListener('face-state', (event) => {
  console.log(event.detail.state);
});
```

Используйте это событие для визуальной синхронизации или старых интеграций. Для бизнес-логики / жизненного цикла Agent и доступного статусного текста предпочтительнее `action-state`.

| Атрибут | Описание |

| `size` | Положительный размер в пикселях. Поддерживаются числа вроде `140` и явные пиксели вроде `140px`. Неподдерживаемые единицы, некорректные строки, ноль, отрицательные и неконечные значения возвращаются к `112px`. |
| `color` | Основной цвет аватара. |
| `auto-sleep` | Время бездействия до автоматического сна в миллисекундах; `0` отключает автоматический сон. |
| `wake-on` | Политика автоматического пробуждения: `activity` (по умолчанию), `interaction` или `manual`. |
| `motion` | Политика движения: `auto` (по умолчанию), `reduce` или `full`. |

Все атрибуты необязательны. Динамическое изменение размера поддерживается; drag-координаты и pointer following используют текущий layout-размер элемента.

## Поведение по умолчанию

Без явных API-вызовов аватар уже предоставляет лёгкое фоновое поведение:

- Случайное моргание
- Лёгкое блуждание взгляда
- Следование за указателем, когда курсор рядом
- Небольшое инерционное движение головы
- Естественный возврат в idle
- Опциональный автоматический сон

`motion="reduce"` или активный системный `prefers-reduced-motion` упрощает эти декоративные движения.

## Drag-взаимодействие

Аватар поддерживает прямое перетаскивание мышью, пером и touch-указателем. Голова локально деформируется вокруг точки взаимодействия вместо движения как жёсткий объект.

- Сильное вытягивание наружу в idle: после восстановления вызывает визуальную реакцию `angry`
- Сильное вдавливание к центру в idle: после восстановления вызывает визуальную реакцию `success`
- Небольшое перетаскивание: только деформация, без выражения
- Активные программные действия вроде waiting/input сохраняют владение выражением; drag-деформация доступна, но декоративная реакция отбрасывается
- `pointercancel`, потеря capture, reset, замена действия и disconnect восстанавливают drag-геометрию без отложенной реакции

Область взаимодействия аватара использует `touch-action: pinch-zoom`: движение одного указателя остаётся доступным для собственного drag-жеста, а pinch zoom двумя пальцами разрешён. Прокрутка страницы, начатая вне аватара, сохраняет обычное touch-поведение страницы. Работа мыши на desktop не меняется.

## Отрисовка и видимость

Компонент приостанавливает постоянную покадровую отрисовку, когда у него нет видимой layout-области или он находится вне viewport. Скрытие родительского контейнера отслеживается через layout/intersection-наблюдение. После возвращения в видимую область аватар продолжает текущее корректное состояние, а не воспроизводит устаревшие действия.

Таймеры конечных действий продолжают завершаться, пока визуальная отрисовка приостановлена, поэтому Promise действий не зависят от непрерывного rendering. Существующие механизмы паузы при скрытой странице и стабильном sleep сохраняются. Observers и медиазапросы экземпляра очищаются при отключении аватара.

## Совместимость

Agent Robot Avatar рассчитан на современные браузеры с поддержкой ES modules, Custom Elements, SVG, Pointer Events, Web Animations API, `IntersectionObserver`, `ResizeObserver` и `matchMedia`.

Автоматизированный browser suite покрывает Chromium, Firefox и WebKit. Отмена доверенного touch-drag дополнительно проверяется через touch emulation Chromium; сведения о проверках на реальных устройствах смотрите в соответствующих PR / release notes.
